# 编写可执行计划

## 计划粒度

一个任务应当：

- 能在一次会话内完成
- 有明确的完成标准
- 有可执行的验证命令
- 不依赖未确认的外部条件

## 任务结构

```markdown
### T-001 实现 H5 缓存命中策略

- 目标：按版本号与过期时间判断缓存是否可用
- 落点：packages/core/src/cache/cachePolicy.ts（或 RN 侧过渡实现）
- 依赖：无
- 验证：单元测试覆盖命中/过期/版本不匹配
- 备注：协议需与鸿蒙端对齐
```

## 拆解步骤

1. 读需求与现有代码
2. 列出涉及的文件与模块
3. 按"共享逻辑 → RN → 鸿蒙 → 联调"排序
4. 每个任务给出验证方式
5. 标注不确定项与需要确认的问题

## 依赖排序

- 先协议/类型，后实现
- 先共享逻辑，后两端接入
- 先主流程，后异常与优化
- 需要外部接口的任务尽量靠后，避免阻塞

## 计划检查

- [ ] 每个任务有唯一编号
- [ ] 每个任务有完成标准
- [ ] 每个任务有验证方式
- [ ] 涉及两端的任务已标注
- [ ] 不确定项已列出
- [ ] 任务之间依赖清晰

## 落盘

- 写入 `docs/tasks/<端>/active/`
- 使用 `[ ]` / `[x]` 标记进度
- 每轮完成后更新，不集中补记

## 避免

- 任务过大（"完成整个功能"）
- 任务过碎（"改一个变量名"）
- 没有验证方式的任务
- 基于猜测的依赖
