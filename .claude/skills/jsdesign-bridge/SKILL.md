# jsdesign-bridge 四步还原闭环

前置条件（详见集成包 docs/mcp-setup.md）：JSDesign 桌面端已打开**目标设计文件**；huabao-design-bridge 插件在目标文件中运行（面板绿点 = 连接正常）。

## 第一步：插件截图画板（视觉基准）

调 `export_asset(画板节点, { format: 'png', scale: 2 })` 导出整画板渲染图——像素级忠实的设计稿基准，直接作为还原输入（无需人工截图）。超长画板可按顶层区块分别截。

## 第二步：AI 看图还原出稿（默认不调 MCP 工具）

凭画板截图直接写语义化 HTML/CSS——视觉直觉写流式布局比坐标转录又快又好。颜色/间距目测近似即可，产出时声明"近似稿，待精确校准"。位图位置用语义占位（如 `<div class="truck-img">`）。

## 第三步：人工核验（差异检测）

用户在浏览器打开产物与设计稿对照，指出"哪里不对"（如"这个卡片颜色不对""少了个按钮"）——人眼是最可靠的差异检测器，且只需指出位置无需描述细节。

## 第四步：MCP 定向校准（只修人工指出的差异）

对差异区块才调 MCP：`get_node_css(差异节点)` 取精确值替换目测值；`export_asset` 补缺失资产（位图原图/图标 SVG，dir 传应用工程内临时目录）。**逐节点全量采集已被此闭环取代，禁止未经核验的全量样式拉取。**

**像素级核对方法**（按结构树逐容器自查，不依赖人眼逐项指认）：
- 每个容器：flex 方向取 `layout`、内边距取 `padding` 标注、子节点间距取相邻 `pos` 坐标差（或 `gap` 标注值）；
- 每个文本节点：font-size/line-height/letter-spacing/font-weight 逐项与 css 轨核对；
- 替换目测值时保留目测版本注释（便于回溯）。

## 工具链参考（第四步按需使用）

```
list_frames                 画板清单（每次强制重新采集 = 文档基线刷新）
  → get_structure(frameId)  单画板轻量结构树（id/名称/类型/尺寸/布局方向，定位节点用）
    → get_node_css(nodeId)  单节点精确样式：css 轨可直接套用（不含定位）+ raw 轨原语保真
    → list_assets(frameId)  规则化枚举候选资产（bitmap / vector 分类）
      → export_asset(nodeId) 按需切图：IMAGE 填充走原图字节，纯图形走 SVG（落盘返路径）
```

## 核心规则（还原与校准通用；多文件/多会话/顺序依赖三条仅第四步）

- **样式**：css 轨不含 left/top（画板坐标套文档流会错位）；文档流布局按结构树的兄弟关系推导 flex/gap/margin；坐标在 raw.x/raw.y 仅作参考
- **尺寸自适应**：画板尺寸（如 375×812）是设计画布不是代码尺寸——页面容器 `width: 100%`（可配 max-width）、高度由内容撑开；固定像素仅用于元素级（图标/图片/间距）
- **系统元素跳过**：移动端状态栏（9:41/信号/电池）、设备外框/手机轮廓是系统界面不是应用 UI——不还原，从应用内容（导航栏或首个区块）开始
- **固定栏常识**：移动端顶部导航栏与底部 tab 栏用 `position: sticky/fixed` + 内容区独立滚动，这是常识性结构，勿随内容流排布
- **布局流式优先**：容器布局以结构树 `layout` 标注为准（row/column → flex 对应方向 + gap；mixed → 先分析叠放关系）。**禁止用 position:absolute 铺常规内容**——absolute 仅限真正的悬浮元素（角标徽章、浮层、开关圆点）
- **页面背景**：画板根节点自己的 fill 就是页面背景色——还原时必须对画板根节点调 get_node_css，勿只采子节点
- **逐节点对齐**：生成 DOM 必须与结构树逐节点对齐，**禁止省略"小"节点**（操作按钮/图标常是 INSTANCE 实例，最易被漏）
- **资产分层**：bitmap（IMAGE 填充）按显示尺寸分流（≤128px 走 PNG@2x，大图走原图字节）；vector 图标优先组件库复用，库中没有的才切 SVG；纯色/渐变背景与文本用 CSS 还原，不切图；横幅/插画区先 list_assets 核对插画资产再动手
- **成品组合位图不直接当背景**：横幅/整卡贴图常是设计师贴入的成品图——文字已烧死且可能是旧数据（实证：位图内"40分钟"vs 设计真值 45分钟）。特征：list_assets 中 bitmap 带 overlapText 标注（与文本节点空间重叠）。正确做法：拆图形子节点分别切（时钟/装饰），文字永远 HTML；位图含烧死旧数据时按「位图烧死数据」规则补丁处理
- **脏稿防御**（设计文件常有标注层/参考底图层）：节点名含 `.png/.jpg` 的 IMAGE 填充 ≈ 贴图参考底图（非 UI），跳过或经用户确认；切出的资产若带标注烙印（蓝框、`xx × xx` 尺寸标签）→ 改选更精确的子节点重导，或先在设计侧隐藏测量标注层
- **位图烧死数据**：资产位图自带文字/旧数据时，用背景补丁盖住烧死区域 + HTML 叠加活文字（数据保留为可变量），勿依赖图内文字
- **渐变/阴影**：css 轨遇 GRADIENT 填充会自动走官方 SVG 提取轨给出 linear-gradient/box-shadow（notes 标注来源），勿用 raw.gradientStops 手算
- **字体加载**：css 轨的 font-family 是设计字体名（如 SourceHanSansCN 思源黑体）——产物**必须实际加载该字体**（web font 链接/本地字体声明），否则观感必然有差；无法加载时在产出中明确声明"字体未对齐"
- **多文件**：桥只读当前激活的设计文件；切换文件后**重调 list_frames 刷新基线**；只让目标文件运行插件（其它页签的插件面板关掉，防连接抢占）
- **多会话**：daemon 单例自动拉起/复用，多个会话可同时使用；空闲 15 分钟自动回收
- **顺序依赖**：list_assets / get_node_css 依赖缓存，对同一画板先 get_structure 建缓存

## 常见错误对照

| 错误信息 | 处理 |
|---|---|
| 插件未连接：请打开并运行… | JSDesign 打开目标文件并运行插件，等面板绿点 |
| 文档中没有画板 | 当前文件无画板，或目标文件未激活——切到目标文件重调 list_frames |
| 画板 xxx 不在缓存 | 先 get_structure(frameId) 建缓存 |
| 超 8MB 上限 | 调低 export_asset 的 scale，或改选更小子节点 |
| 返回的 fileName 与目标文件不符 | 连接的是另一个文件的插件——切到目标文件重跑插件后再试 |
