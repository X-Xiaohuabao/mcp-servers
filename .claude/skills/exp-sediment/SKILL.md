# 经验沉淀

## 目标

把隐性知识转化为显性资产，下次遇到同样问题不必重新踩坑。

适用仓库：mcp-servers（MCP 集成仓库）。

## 经验分类

| 类型 | 特征 | 去向 |
|---|---|---|
| 踩坑记录 | 某操作导致失败，有明确原因 | `docs/experience/` |
| 反复纠正 | 用户多次指出同一做法 | 更新对应 skill |
| 重复模式 | 同类代码反复出现 | 更新 skill 或 AGENTS.md |
| 硬性约束 | 违反会导致事故 | `AGENTS.md` |
| 流程改进 | 步骤可优化 | 更新 command |
| 工具用法 | 某命令/配置的正确用法 | `docs/experience/` 或 skill |

## 流程

1. **收集**
   - 回顾本次会话中用户纠正过的地方
   - 查看最近提交：`git log --oneline -20`
   - 找出重复出现的问题

2. **筛选**
   - 是否可复用？一次性的不沉淀
   - 是否能从代码或 git 历史直接得到？能则不沉淀
   - 是否已经在文档中？在则不重复

3. **分类**：按上表确定去向

4. **确认**：把建议列给用户，用户决定是否落地

5. **落盘**
   - 更新 skill：触发词维护在 SKILL.md frontmatter 的 `触发词` 行，hook 动态扫描自动生效，无需改 hook
   - 更新 `AGENTS.md`：只放硬性约束
   - 经验文件：`docs/experience/YYYY-MM/YYYY-MM-DD-<简述>.md`

## 质量要求

每条经验必须有：

- **背景**：什么场景
- **原因**：为什么会这样（Why）
- **做法**：正确做法是什么
- **适用范围**：插件侧 / server 侧 / 仓库级流程

## 不沉淀的内容

- 代码结构、文件路径（读代码即可得）
- 单次任务的临时状态
- 已在 AGENTS.md 中的规则
- 无原因的"不要这样做"

## 验证

- 更新 skill 后确认 frontmatter 与触发词有效
- 更新 AGENTS.md 后确认与现有条目不冲突
- 经验文件的日期与命名符合规范
